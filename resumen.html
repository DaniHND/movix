🚕 ¿Qué es Movix?

Movix es una aplicación web para pedir taxi, similar a Uber o inDriver, pero diseñada específicamente para Tegucigalpa, Honduras. La diferencia con una app de celular es que Movix funciona directamente desde el navegador web (Chrome, Firefox, Safari) y puede instalarse como si fuera una app nativa en el teléfono sin necesidad de ir a una tienda de aplicaciones.

🧑‍💻 En palabras simples Imagina que abres Chrome en tu teléfono, entras a la dirección de Movix, y el navegador te pregunta "¿Quieres instalar esta app?". Le das que sí, y aparece en tu pantalla de inicio como cualquier otra app — con ícono, pantalla de carga y todo. Eso es una PWA (Progressive Web App).

El sistema tiene tres tipos de usuarios: clientes que piden taxi, conductores que aceptan viajes, y administradores que gestionan todo desde un panel de control.

🏠 Los 3 portales

👤

Portal Cliente

Donde el pasajero pide su taxi. Tiene mapa con Google Maps, calcula el precio antes de confirmar, muestra al conductor en tiempo real y permite chatear con él.

/cliente
🚗

Portal Conductor

Donde el taxista gestiona su trabajo. Puede activarse/desactivarse, ver viajes disponibles, aceptarlos, iniciarlos y completarlos. El GPS manda su ubicación en tiempo real.

/conductor
⚙️

Portal Admin

Panel de control para el equipo de Movix. Aprueba o rechaza conductores, configura precios por kilómetro, revisa todos los viajes y crea cupones de descuento.

/admin

🛠️ Tecnologías usadas

🖥️
PHP — El cerebro del servidor
  • Versión 8.1+
  • Arquitectura MVC
  • Sin framework externo

PHP es el lenguaje que corre en el servidor. Recibe las peticiones del usuario, habla con la base de datos y devuelve la página. Es como el cocinero de un restaurante: el cliente pide algo (clic), el mesero lo lleva a la cocina (PHP), y la cocina prepara y devuelve el plato (la página HTML).

🗄️
MySQL — La base de datos
  • Versión 8
  • 13 tablas
  • PDO con prepared statements

MySQL es donde se guarda TODA la información: usuarios, viajes, chats, precios, etc. Piénsalo como una colección de hojas de cálculo muy poderosas donde cada fila es un registro (un viaje, un usuario) y cada columna es un dato (nombre, precio, fecha).

🎨
HTML + CSS — Lo que ves
  • HTML5 semántico
  • CSS3 Vanilla (sin Bootstrap)
  • Mobile-first desde 375px

HTML es el esqueleto de la página (dónde va cada texto, botón e imagen). CSS es el diseño: colores, tamaños, animaciones. No se usó Bootstrap ni ningún kit de diseño externo — todo fue construido a mano para que sea liviano y rápido.

⚡
JavaScript — Lo interactivo
  • ES6 Vanilla (sin jQuery)
  • Fetch API para peticiones
  • requestAnimationFrame

JavaScript corre directamente en el navegador del usuario y hace todo lo que no requiere recargar la página: actualizar el mapa en tiempo real, mostrar el precio mientras escribes el destino, el chat que recibe mensajes sin refrescar, etc.

🗺️
Google Maps API
  • Mapa interactivo
  • Autocomplete de direcciones
  • Cálculo de rutas

El mismo servicio que usa la app de Google Maps. Movix lo integra para mostrar el mapa al pedir un viaje, sugerir direcciones mientras el cliente escribe y dibujar la ruta del conductor al destino.

🔔
Firebase FCM — Notificaciones
  • Push al conductor
  • Service Worker
  • Funciona en segundo plano

Cuando un cliente pide un taxi, el conductor recibe una notificación en su teléfono aunque no tenga la app abierta — como un mensaje de WhatsApp. Eso es Firebase Cloud Messaging (FCM), el servicio de notificaciones de Google.

📧
PHPMailer — Correos
  • Verificación de cuenta
  • Recuperación de contraseña
  • Plantillas HTML en emails

Librería que envía correos electrónicos desde el servidor. Se usa para enviar el link de verificación cuando te registras, y para restablecer la contraseña si la olvidaste.

📲
PWA — App instalable
  • Funciona offline (parcial)
  • Instalable en pantalla de inicio
  • Sin tienda de apps

Tecnología que convierte el sitio web en algo que se puede instalar y usar como una app nativa, sin necesitar Google Play ni App Store. El navegador descarga los recursos principales para que cargue rápido.

🏗️ Cómo está organizado el código (Arquitectura MVC)

🧑‍💻 Para no programadores: ¿Qué es MVC? MVC (Modelo-Vista-Controlador) es una manera de organizar el código para que sea más fácil de mantener. Imagina un restaurante:

• Modelo = La cocina y la despensa. Sabe cómo guardar y obtener información de la base de datos.
• Vista = El plato que llega a tu mesa. Es el HTML que el usuario ve en pantalla.
• Controlador = El mesero. Recibe lo que pide el cliente, le dice a la cocina qué preparar, y entrega el resultado.

Fase 1 — Base de datos, Rutas y Login ✅ Completo
Los cimientos del sistema: dónde se guarda todo, cómo funciona la navegación y cómo entran los usuarios

📊 Base de datos

🧑‍💻 En palabras simples La base de datos es como el archivo principal de la empresa. Contiene carpetas (tablas) para: los clientes registrados, los conductores y sus vehículos, cada viaje realizado, los precios por kilómetro, los mensajes de chat, los cupones de descuento, y más. Todo lo que el sistema "recuerda" vive aquí.
  • usuarios — clientes registrados (nombre, correo, contraseña cifrada)
  • conductores — taxistas con sus documentos, estado (pendiente/aprobado), GPS actual
  • vehiculos — el carro de cada conductor (marca, modelo, placa, fotos)
  • viajes — cada viaje: quién lo pidió, quién lo llevó, origen, destino, precio, estado
  • tarifas — precios por km según distancia y horario (día/noche, convencional/VIP)
  • mensajes_chat — los mensajes entre cliente y conductor durante el viaje
  • cupones / cupones_uso — códigos de descuento y quién los ha usado
  • notificaciones_viaje — historial de notificaciones enviadas
  • estadisticas_diarias, comisiones_pagos — datos para reportes del admin
  • admins — usuarios del panel de administración

🔀 Sistema de rutas (Routing)

🧑‍💻 En palabras simples Cuando escribes una dirección en el navegador (como movix.com/cliente/historial), el sistema necesita saber qué página mostrarte. El sistema de rutas es como un recepcionista que lee la dirección y te dirige al departamento correcto.
  • Todas las peticiones llegan a un solo archivo: public/index.php
  • Ese archivo lee la URL (/cliente, /admin, /api/viaje/5…)
  • Consulta la tabla de rutas en config/routes.php y llama al Controller correspondiente

🔐 Autenticación (Login y registro)

🧑‍💻 En palabras simples El sistema de login verifica que eres quien dices ser. Las contraseñas nunca se guardan en texto plano — se convierten en un código cifrado (hash) que es imposible revertir. Para recuperar la contraseña, el sistema envía un link único por correo que expira en 1 hora.
  • Una sola pantalla de login para los 3 portales, con pestañas para cambiar entre ellos
  • Registro de clientes con verificación por correo electrónico (link de activación)
  • Recuperación de contraseña: link de un solo uso que expira en 1 hora
  • Contraseñas protegidas con bcrypt (algoritmo de cifrado estándar)
  • Protección CSRF: cada formulario lleva un código secreto único para evitar envíos falsos
  • La sesión expira automáticamente: 4 horas para admins, 8 horas para clientes y conductores

Fase 3 — Portal del Conductor ✅ Completo
La app del taxista: registro con documentos, activarse/desactivarse, aceptar y completar viajes

📝 Registro del conductor

🧑‍💻 Cómo funciona Un conductor nuevo llena un formulario con sus datos personales, los datos de su vehículo y sube fotos de sus documentos. Su cuenta queda en estado "Pendiente" hasta que un administrador revise los documentos y la apruebe. Solo entonces podrá empezar a recibir viajes.
  • Datos personales: nombre, fecha de nacimiento, número de identidad, teléfono, correo, contraseña
  • Datos del vehículo: marca, modelo, año, placa, color, número de taxi (opcional)
  • Tipo de servicio: Convencional o VIP
  • Documentos subidos: foto de perfil, identidad (frente y reverso), licencia de conducir (frente y reverso), foto del vehículo
  • Estado inicial: Pendiente — el admin debe aprobar antes de que pueda operar

📍 Dashboard del conductor (Pantalla principal)

🧑‍💻 Cómo funciona Una vez aprobado, el conductor entra a su app y ve un interruptor "Conectado / Desconectado". Cuando lo activa, el sistema empieza a enviar su ubicación GPS al servidor cada 15 segundos. Así, cuando un cliente pide un taxi, el sistema puede encontrar al conductor disponible más cercano.
  • Interruptor visual Online/Offline (toggle verde animado)
  • Cuando está Online: el GPS del teléfono envía la posición cada 15 segundos al servidor
  • Lista de viajes pendientes disponibles para tomar
  • Botones de acción: Tomar viaje → Iniciar viaje → Completar viaje
  • Si tiene un viaje activo, muestra los datos del cliente y el destino
  • Historial de viajes realizados
  • Perfil: editar teléfono

Fase 5 — GPS en Tiempo Real y Asignación Automática ✅ Completo
El conductor aparece en el mapa moviéndose, y el sistema encuentra al taxista más cercano automáticamente

🤖 Asignación automática del conductor

🧑‍💻 Cómo funciona Cuando un cliente pide un taxi, el sistema hace un cálculo matemático para encontrar al conductor disponible MÁS CERCANO en un radio de 10 km. Usa una fórmula llamada "Haversine" que calcula la distancia real entre dos puntos del mapa usando sus coordenadas GPS (latitud y longitud). No es necesario un conductor humano asignando viajes — todo es automático.
  • Radio de búsqueda: 10 km alrededor del cliente
  • Solo busca conductores: Online, Aprobados, del mismo tipo (Convencional/VIP) y sin viaje activo
  • Si no encuentra conductor, el viaje queda en espera
  • Al asignar, envía una notificación push al teléfono del conductor

📍 Seguimiento del conductor en tiempo real

🧑‍💻 Cómo funciona Una vez asignado el conductor, el cliente ve un mapa con el ícono del carro moviéndose hacia él. Esto funciona así: cada 5 segundos, el navegador le pregunta al servidor "¿dónde está el conductor ahora?", y si cambió de posición, el ícono en el mapa se anima suavemente hasta la nueva posición (como un GPS de rastreo en tiempo real). También muestra el tiempo estimado de llegada (ETA).
  • El ícono del conductor se mueve suavemente en el mapa (animación de 20 pasos)
  • ETA actualizado: calcula cuántos minutos faltan según la distancia actual a velocidad promedio urbana
  • Estados visibles: "Conductor en camino" → "Conductor llegó" → "Viaje en curso" → "Completado"
  • Cuando el viaje termina, la página se recarga automáticamente

Fase 6 — Chat, Cupones, Gráficas y Notificaciones Push ✅ Completo
Comunicación entre cliente y conductor, descuentos, estadísticas visuales y notificaciones al teléfono

💬 Chat entre cliente y conductor

🧑‍💻 Cómo funciona Durante el viaje, el cliente y el conductor pueden enviarse mensajes de texto. Funciona como un chat básico tipo WhatsApp, pero sin usar WhatsApp. La pantalla del cliente y la del conductor se actualizan automáticamente cada 4 segundos para mostrar mensajes nuevos, sin necesidad de recargar la página.
  • Chat disponible mientras el viaje está en curso (asignado o en_curso)
  • Globos de chat: mensajes propios a la derecha (azul), recibidos a la izquierda (gris)
  • Contador de mensajes sin leer en la pestaña del chat
  • Máximo 500 caracteres por mensaje

🎟️ Cupones de descuento

🧑‍💻 Cómo funciona El admin crea cupones con un código (ej: BIENVENIDO) y un porcentaje de descuento. El cliente escribe el código antes de confirmar el viaje, y el sistema valida que sea válido, no haya vencido y no lo haya usado antes. Si todo está bien, el precio baja automáticamente. Al completar el viaje, el cupón se marca como "usado" para ese cliente.
  • BIENVENIDO: 20% de descuento (incluido en datos de prueba)
  • MOVIX10: 10% de descuento (incluido en datos de prueba)
  • Validación doble: primero en el navegador (inmediata), luego en el servidor (segura)
  • Protección anti-fraude: un cliente no puede usar el mismo cupón dos veces

📈 Gráficas de estadísticas

🧑‍💻 Cómo funciona El dashboard del admin muestra dos gráficas de líneas: una con la cantidad de viajes por día en los últimos 30 días, y otra con los ingresos. Estas gráficas fueron construidas completamente a mano, sin usar ninguna librería externa como Chart.js — usando directamente el elemento "canvas" de HTML5.

🔔 Notificaciones push (Firebase FCM)

🧑‍💻 Cómo funciona Cuando un cliente pide un taxi y el sistema lo asigna a un conductor, ese conductor recibe una notificación en su teléfono aunque la app no esté abierta — igual que cuando recibes un WhatsApp con la pantalla apagada. Esto funciona gracias a Firebase Cloud Messaging (FCM), el servicio de notificaciones push de Google.

Fase 7 — App Instalable, Seguridad y Configuración de Producción ✅ Completo
Convierte el sitio en una app instalable, protege contra ataques y prepara todo para el servidor real

📲 PWA — Progressive Web App (App instalable)

🧑‍💻 Cómo funciona Cuando un usuario abre Movix en Chrome en su teléfono Android, el navegador detecta que el sitio cumple los requisitos para ser instalado como app. Aparece un banner "¿Instalar Movix?" y si acepta, la app queda en la pantalla de inicio del teléfono con su ícono azul, abre en pantalla completa sin la barra del navegador y carga rápidamente porque guarda los recursos en el teléfono.
  • manifest.json: le dice al navegador cómo debe verse la app instalada (nombre, ícono, colores)
  • ícono SVG: la letra "M" de Movix en fondo azul con barra roja — el ícono que aparece en la pantalla de inicio
  • Service Worker (sw.js): un script que corre en segundo plano y guarda en caché los archivos CSS/JS/imágenes para que carguen instantáneamente. Las páginas HTML NO se cachean (para que el logout funcione correctamente)
  • Botón "Instalar app": aparece en el portal cliente cuando el navegador soporta la instalación

🔒 Seguridad

🧑‍💻 Por qué es importante Un sistema de taxi maneja datos personales y ubicaciones de personas. Es fundamental protegerlo contra intentos de hackeo. Se implementaron varias capas de protección.
  • Rate Limiting: si alguien intenta adivinar una contraseña, se bloquea después de 5 intentos fallidos durante 15 minutos. Protege contra ataques de fuerza bruta.
  • CSP (Content Security Policy): regla que dice exactamente de qué sitios externos puede cargar recursos el navegador. Evita que alguien inyecte código malicioso.
  • CSRF Protection: cada formulario lleva un código secreto único. Si alguien intenta enviarte a una página trampa que envíe un formulario, el código no coincidirá y se rechaza.
  • HTTPS redirect: configurado y listo para activar en producción — redirige todo tráfico HTTP a HTTPS (conexión cifrada)

🚀 Configuración para producción

  • nginx.conf.example: plantilla completa de configuración para el servidor web Nginx con SSL, compresión y caché
  • .env.example: template con todas las variables que hay que configurar (base de datos, API keys, correo) con comentarios explicativos
  • .gitignore: protege para que contraseñas y logs nunca se suban a GitHub

El conductor adjunta sus documentos al registrarse; el admin los revisa antes de aprobar la cuenta

📄 ¿Qué documentos sube el conductor?

🧑‍💻 Cómo funciona Al registrarse, el conductor llena el formulario normal (datos personales y del vehículo) y al final tiene una sección para adjuntar fotos o archivos PDF. Una vez enviado, el sistema guarda los archivos de forma segura en el servidor y el admin puede verlos en el detalle del conductor para tomar la decisión de aprobar o rechazar.

🔐 Seguridad de los archivos

  • Cada archivo recibe un nombre aleatorio de 32 caracteres (ej: a3f7c2d1...) — nadie puede adivinar la URL
  • Tamaño máximo: 8 MB por archivo
  • El sistema verifica el tipo real del archivo (no solo la extensión) — no se puede subir un .exe renombrado como .jpg
  • Si algún documento falla, los que ya se habían subido se eliminan automáticamente (sin archivos huérfanos)
  • Los archivos se guardan en public/uploads/ con un .htaccess que bloquea la ejecución de PHP dentro de esa carpeta

👁️ Revisión por el admin

  • En la página de detalle de cada conductor, el admin ve una galería con miniaturas de todas las fotos
  • Al hacer clic en una miniatura, se abre la imagen en tamaño completo en una nueva pestaña
  • Los PDFs se muestran con un ícono de documento y un link "Ver PDF"
  • Con toda la información visible, el admin puede Aprobar, Rechazar o Suspender al conductor

Correcciones de bugs Corregidos
Problemas encontrados durante las pruebas y cómo se resolvieron
ProblemaCausaSolución
Cliente atrapado en "Buscando conductor" sin poder cancelar Los botones "Cancelar" y "Volver" estaban al fondo de la pantalla, fuera de la vista en móviles pequeños Se movieron al inicio de la pantalla para que siempre sean visibles
Botón "Cancelar" no aparecía para viajes ya asignados El código solo mostraba el botón para viajes en estado "pendiente", no para "asignado" Se amplió para mostrar el botón en ambos estados
El cliente no podía cerrar sesión desde el portal El menú de navegación del cliente no tenía botón de "Salir" Se agregó "Salir" como quinto ítem del menú inferior
Después de cerrar sesión, la app seguía mostrando la pantalla anterior El Service Worker estaba guardando las páginas en caché, incluidas las que requieren login Se configuró el SW para que NUNCA guarde páginas HTML — solo archivos CSS, JS e imágenes
Error en la consulta SQL de asignación automática PDO no permite usar el mismo nombre de parámetro dos veces en la misma consulta (ej: :lat) Se usaron nombres distintos :lat_a y :lat_b con el mismo valor
El archivo manifest.json era bloqueado y la PWA no funcionaba Una regla de seguridad bloqueaba todos los archivos .json, incluyendo el necesario para la PWA Se ajustó la regla para bloquear solo los archivos sensibles específicos
